# ANDLINE: Premium на одном Bungee/NullCordX и GML Authlib

> Дизайн для интеграции. Этот PR добавляет только изолированный проверяемый
> реестр маршрутов, НЕ подключает его к действующему преобразованию URL,
> НЕ разрешает Premium-вход и НЕ изменяет поведение модовых серверов.

## Требования пользователя

1. Все новые игроки регистрируют ANDLINE-аккаунт обычным способом.
2. Авторизованный игрок использует `/premium`, получает понятное предупреждение
   и явно подтверждает начало привязки официальной Minecraft Java Edition.
3. При следующем входе сервер требует настоящую онлайн-сессию Mojang.
   Клиент, который не проходит encryption + официальный `hasJoined`, не
   подтверждает ничего; заявка истекает, прежний режим сохраняется.
4. Подтверждённый *официальный UUID* связывается с конкретным `users.id`.
   Ни ник, ни клиентский флаг «премиум», ни IP не считаются доказательством.
5. После привязки offline/TLauncher-способ для этого ANDLINE-аккаунта
   запрещён ещё на стадии PreLogin, **даже с правильным паролем**.
   Проверенный GML Custom Yggdrasil остаётся допустимым с его
   отдельной авторизацией и актуальной политикой 2FA.
6. Отключить режим может только владелец после усиленной повторной проверки:
   подтверждение в Telegram/VK или подтверждённая официальная/GML-сессия
   с дополнительным фактором, когда он требуется. Offline-команда не снимает блок.
7. Серверов-прокси **один**, отдельные модовые серверы со своим authlib не меняем.

## Состояния и инварианты

```text
OFFLINE_ALLOWED
  -> LINK_PENDING (короткая заявка, привязка ещё НЕ активна)
  -> VERIFIED_PREMIUM_OR_GML (только после hasJoined и уникальной привязки Mojang UUID)
  -> RECOVERY_PENDING (усиленная повторная проверка)
  -> OFFLINE_ALLOWED
```

- **Ник не определяет источник клиента**. Виртуальный хост, параметр handshake
  или `online-mode` разрешают лишь **выбрать проверку**, но не подтверждают
  учётную запись.
- Одновременно может быть только одно активное связывание пользователя.
- Строго отдельные `offline_uuid` (канонический ANDLINE), `mojang_uuid`
  (официальная идентичность), `gml_uuid`. Никогда не переписывать
  `users.uuid` на Mojang UUID.
- Нужна таблица `player_auth_identities(user_id, provider, external_uuid,
  verified_at, revoked_at, auth_revision)` с уникальными
  `(provider,external_uuid)` и необходимыми индексами.
- Политика `PREMIUM_OR_GML` хранится **в Laravel**, не в памяти прокси,
  не в `PremiumCache` и не в устаревшей локальной `auth_users`.
- Вся выдача игровых привилегий/сессии происходит после уникального
  `session.claim` и `PostAuthSessionGate`.
- Активная 2FA сайта не должна обходиться из-за отсутствия bot binding.

## Почему одного -javaagent=GML недостаточно

Штатный `DefaultURLRedirector` глобально переписывает запросы к
`sessionserver.mojang.com` на `GML/sessionserver` внутри **целой JVM**.
Переключение `connection.setOnlineMode(true)` не превращает такую
проверку в проверку оригинальной лицензии.

Для надёжной реализации в том же процессе нужны:

1. Адаптер Bungee/NullCordX к точке расчёта реального `serverId` после
   encryption handshake; именно здесь привязываются `PendingConnection`
   и серверный hash. **Регистрировать по нику в PreLogin нельзя.**
2. `AndlineSessionRouteRegistry.reserve(serverHash, exactName, MOJANG|GML,
   connectionId, ttl)` из доверенного адаптера. Ник и виртуальный хост
   от клиента не дают права вызвать этот API самостоятельно.
3. Запрос `hasJoined` должен попасть в изолированный локальный обработчик
   Agent, который выполняет `consume(serverHash,exactName)`; отсутствие
   маршрута -> отказ, никогда fallback на offline, GML или Mojang.
4. Обработчик направляет HTTPS-запрос строго к соответствующему backend:
   `https://sessionserver.mojang.com/session/minecraft/hasJoined` либо к
   закреплённому GML CustomEndpoint, без пользовательских URL,
   открытых редиректов или отправки токенов в логи.
5. Положительный ответ провайдера должен содержать истинные `id/name`,
   проверенные против фактического аккаунта ANDLINE. Результат связывается
   с **тем же connectionId** перед `PostLogin`, без передоверия полю,
   присланному Minecraft-клиентом.
6. Адаптер публикует подтверждённый результат в TiAuth. TiAuth сверяет
   решение с сайтом (активность, политика, единственная привязка UUID,
   актуальность 2FA/GML) и передаёт подключение через существующий
   одноразовый admission/claim.
7. Требуются E2E-тесты с реальным официальным клиентом, GML Custom
   Yggdrasil и offline/TLauncher на одном прокси; проверка имён,
   коротких сессий, двойных коннектов, отказов провайдера, отключений Node.

## Примеры, которые **нельзя** считать успешным подтверждением

- «Клиент не кикнуло после включения online-mode» без проверки `hasJoined`.
- «Ник существует у Mojang» или официальный UUID найден в API.
- «Игрок подключился через premium.example.org».
- «Клиент передал Mojang UUID/свойства профиля».
- Нажатие `/premium` без повторной проверки личности.
- Автоматический возврат на пароль после неуспешной/недоступной
  онлайн-верификации уже премиум-привязанной учётной записи.

## Статус этого PR

**FOUNDATION / NOT FOR DEPLOYMENT.** Реестр
`AndlineSessionRouteRegistry` не подключён к `URLProcessor` и не
используется в авторизации. Добавлены тесты для single-use, чужого
connection owner, истечения срока, гонки параллельных подтверждений,
строгого serverHash+username и запрета смены провайдера посреди входа.

Новый endpoint или настройка в `config.yml` пока не требуется.
Настройки сценария и его audit log — в админке ANDLINE;
в окружении только реальные секреты и безопасная конфигурация JVM.
